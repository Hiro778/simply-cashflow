# Simply Cashflow — Privacy & Security Architecture

**Version:** 2.0.0  
**Status:** Verifiable Zero-Cloud, 100% Local-First Architecture  

---

## 1. Absolute Privacy Principles

Simply Cashflow 2.0 is built around an uncompromising privacy philosophy: **your financial data belongs exclusively to you on your device**.

The application enforces the following guarantees:
1. **100% Local Data Processing:** All financial transactions, calculations, budgeting algorithms, and savings metrics execute on the local smartphone CPU.
2. **Zero Remote Cloud Database:** There is no Firebase, Supabase, AWS, MongoDB, or external cloud database connected to the application.
3. **No Mandatory Account or Registration:** No email, phone number, password, or third-party OAuth login (Google, Facebook, Apple) is required or collected.
4. **No Telemetry or Tracking SDKs:** Zero analytics trackers (Google Analytics, Mixpanel, Segment, Flurry, Adjust) or advertising identifiers are integrated.
5. **No External AI APIs:** All natural language classification and notification parsing utilize deterministic local regex engines. No prompt or financial data is transmitted to OpenAI, Anthropic, Google, or any remote LLM.
6. **No Background Data Synchronization:** The app initiates no background network requests to synchronize financial records.
7. **All Features Function Completely Offline:** Flight mode or complete lack of internet connectivity does not impair any application feature.

## 2. Network Audit & Runtime Behavior

### Production Runtime Network Policy
During execution, the application executes **0 network requests** involving financial or personal data.

- **Developer / CI Environment:** The internet is utilized exclusively by developer tooling (e.g. `npm install`, Gradle dependency resolution, and GitHub Actions runner setup).
- **Application Manifest:** The application requests standard Android system permissions for local rendering, but transmits no financial payload.

### Dependency Audit
Inspecting `package.json` confirms:
- No tracking SDKs (e.g. `react-native-firebase`, `@segment/analytics-react-native`, `expo-tracking-transparency`).
- No advertising modules (e.g. `react-native-google-mobile-ads`).
- Local-only utilities: `expo-sqlite`, `expo-file-system`, `expo-sharing`, `zustand`, `lucide-react-native`.

## 3. Smart Capture & Notification Permission Architecture

Smart Capture allows automatic recognition of transaction notifications generated by Indonesian banking and e-wallet applications.

### Android Permission Model
- **Permission Requested:** `android.permission.BIND_NOTIFICATION_LISTENER_SERVICE`
- **Activation Flow:** The user must explicitly navigate to the Android system settings (*Notification Access* / *Akses Notifikasi*) and enable Simply Cashflow.
- **Revocation Safety:** If the user revokes notification access, Simply Cashflow detects the status change gracefully without crashing or degrading core functionality.
- **Strict Package Filtering:** `SmartCaptureService` immediately ignores any notification whose package does not match supported financial apps (e.g. personal messages from WhatsApp, Telegram, SMS, emails, and system alerts are discarded instantly at the native layer without reading).
- **Non-Financial Drop Rule:** Sensitive text such as OTP verification codes, password resets, or promotional campaign alerts are filtered locally by `isNonFinancialAlert()` and discarded immediately.
- **No SMS Permission:** Simply Cashflow does NOT request `android.permission.READ_SMS` or `RECEIVE_SMS`. It does NOT utilize `AccessibilityService`.

## 4. Local Cryptographic Deduplication

To prevent duplicate transaction logging when an e-wallet re-posts or updates an ongoing status notification:
1. A unique payload fingerprint is generated locally:
   $$\text{Fingerprint} = \text{djb2} \left( \text{Package} + \text{Title} + \text{Body} + \left\lfloor \frac{\text{Timestamp}}{300\,000} \right\rfloor \right)$$
2. Notifications with identical content within the 5-minute bucket window are treated as updates and will not trigger duplicate transaction entries.
3. Raw notification strings are retained only in the local diagnostic audit log (`captured_notifications`) and can be cleared by the user at any time in **Settings > Data Management**.

## 5. Data Sovereignty & Portability

- **Local SQLite Database:** Stored strictly within the Android private app sandbox (`/data/user/0/com.hiro778.simplycashflow/databases/simplycashflow.db`), inaccessible to other non-root applications.
- **Encrypted Sandbox:** Modern Android versions (Android 10+) enforce file-based encryption (FBE) at rest for private application storage.
- **JSON Snapshot Export:** Users can generate a clean, unencrypted JSON backup of their entire financial database at any time. The file is saved using Android's system document picker or shared directly via Android ShareSheet.
- **CSV Portability:** All transactions can be exported to standard CSV format for inspection or personal archiving in Microsoft Excel, LibreOffice, or Google Sheets.
- **Complete Wipe:** Users can execute a factory data reset from **Settings > Hapus Semua Data**, which issues `DELETE FROM` across all SQLite tables.
